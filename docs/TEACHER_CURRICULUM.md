# 教員向け：SPICA対応レッスン

## 授業での位置付け

notebookで導入し、LAVi-SPICAで基礎を練習した後に、Pythonが実際の表現につながる例として紹介します。本教材の全課題を授業内必修にする前提ではありません。第1〜5レッスンをSPICAの概念順に合わせ、第6〜7レッスンは選択発展として区別します。

## 設定を編集する

`assets/data/curriculum.json`に学習順、見出し、説明、SPICAのトピックID、例題、開始コード、指示、確認条件、3段階のヒント、解答例、解説をまとめています。

各活動の`code`は学生の開始コード、`solution`は折りたたんで表示する一例です。課題のコア処理は`...`にし、コメントのTODO番号と画面の指示を対応させます。未完成判定はPythonの構文木でEllipsisを探すため、コメント中のTODOは残して構いません。

`spicaBaseUrl`と各lessonの`links`で復習先を管理します。確認したルートは`#learn/<lesson-id>`です。例：`01-variables`、`10-for`、`14-def`。実際のSPICAに存在するIDだけを指定してください。

直接案内するURLは`lessons.html?lesson=loops&activity=practice`のような形式です。lessonはvariables、lists、loops、conditions、functions、random、arrangement、activityはexample、practice、advancedです。

## 確認エンジン

`assets/python/caya_assessment.py`が学生コードを実行し、曲データ・返り値・別入力での動作を確認します。`ast`による構文確認は、コメントに含まれる単語を使用済み構文と誤認しないためのものです。文字列の完全一致で解答を採点するものではありません。

関数では入力の非破壊、新しい返り値、空入力・0回を確認します。休符では音数だけでなく開始時刻と末尾を含む曲の長さを確認します。浮動小数点比較には許容差があります。最終作品では音名を固定せず、トラックの長さと関数の一般性を確認します。

データや問題条件を変更した際は、同じIDのPython確認処理とテストも変更してください。表示文だけを変えて採点条件を放置しないでください。問題内容を大きく変えるときは`courseId`だけでなく保存prefixとIDの移行方針も検討してください。

これはブラウザ内の形成的フィードバックです。学生コードは同じPython環境で実行されるため、不正耐性のある試験採点には使わないでください。チェック通過は、テストした条件での達成を意味します。意味の説明、独力で書いたかどうか、作品の美しさを自動で判定しません。

## 既存機能と保存

`legacy-lessons.html`は旧レッスンと旧保存キーを維持します。新レッスンは別prefixを使い、旧版の「変更して実行済み」を新課題の「条件確認済み」へ昇格しません。作曲スタジオ、曲データ形式、音声エンジン、Colabスターターは維持します。

新レッスンはコード、試行数、最新の結果とその時点のコード、ヒント段階、解答参照、振り返りを保存します。コードを変更すると最新結果を未確認扱いにし、以前の成功を現在のコードへ流用しません。旧保存キーは書き出しに含めますが、新学習記録の読み込みで旧スタジオへ書き戻すことはありません。

## 検証

`npm test`で既存機能と新課題の例題・開始コード・解答例・代表的誤答・別解・保存処理を確認します。`npm run serve`でローカル表示します。

ブラウザの確認ではPython実行環境の初回読み込み、実行と音データ、解答参照と判定の分離、編集後の未確認化、問題切替と保存、記録の再読み込み、狭い画面を確認してください。音声再生にはユーザー操作が必要で、端末固有の実音の聞こえ方は教室の端末でも確認してください。

`npm run package`は追跡中のファイルを、展開時に現在の版番号（v1.2.0）となるZIPへまとめます。今回の作業ブランチは公開mainを自動で変更しません。PRをレビューし、既存のPagesデプロイ手順で反映してください。
